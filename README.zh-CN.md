# VbeComplete · C# 版

*[English](README.md) · 简体中文*

与 Python 版（同级目录 `..\VbeComplete-PY`）同一套 VBA 编辑器补全工具，用 C# 重写，独立仓库。
VBE 原生从不补全**你自己声明**的名字，本工具补的就是这一块。支持 **Office 全家桶**
（Excel / Word / PowerPoint / Access / Visio）与 **WPS 全家桶**，按前台窗口自动识别宿主。

C# 版存在的理由只有一个：**不在 VBE 代码窗里时，一个 COM 调用都不发**，空闲时消息循环不占 CPU。

## 功能

- **实时候选**：标识符 / 声明 / 过程 / 模块 / 窗体 / 控件 / 关键字 / 内建函数
  （171 个函数 + 13 个类型 + 79 个关键字，外加你自己的词库）。
- **类型图标、详情行、永不抢焦点**：候选窗全自绘，不会把插入符从编辑器上夺走。
- **智能确认**：`Tab` / `Enter` 补全；`Sub` 补空格，`Function` 补 `()` 且光标在括号里；
  注释 / 字符串里、点号后、正在声明新名字时一律不打扰。
- **回车自动缩进**：块结构开头深一级并补 `End If` / `Next` / `Loop`；
  `Else` / `Case` 这类分支行先拉回层级。
- **`Shift+Enter`**：在当前行下方新起一行，不拆开本行。
- **退格两用**：删掉只有空白的整行；或把中间的空括号 / 空引号两端一起删掉。
- **自动配对** `(` `"`：中文标点档下补全角 `（）` / `“”`；右边已是收符号就跨过去；
  有选区时用符号包起来。
- **行操作快捷键**：`Ctrl+/` 注释切换 · `Ctrl+D` 复制行 · `Ctrl+K` 删行 ·
  `Ctrl+Shift+Enter` 上方插行 · `Ctrl+Shift+↑/↓` 跳到上一条声明 / 过程收尾行。
- **`Ctrl+Q` 代码片段库**：直接读 Python 版同一个 `snippets.db`（SQLite，标题模糊搜索，
  插入到光标处）。
- **自适应轮询**：打字时 50ms、停手 150ms、不在 VBE 里 250ms。

## 优点

- **不写 VBA 时几乎零开销**：约 0.13% 的一个核、私有内存 11.7MB —— 不在 VBE 代码窗里
  一个 COM 都不发（Python 版同场景约 2% / 29MB）。
- 启动快：单个约 334KB 的可执行文件（框架依赖），没有解释器预热。
- 与 Python 版共用同一个片段库，两边切换不丢数据。
- 所有快捷键遵守同一条铁律：**做不成就把原按键原样还回去**，不会静默吞键。
- 205 条自检 + 片段库检查 + 两条真机探针，逻辑改动都有回归兜底。

## 缺点

- 需要 **.NET 10 桌面运行时**，且只支持 Windows。
- 必须勾选"信任对 VBA 工程对象模型的访问"（默认关闭），与 Python 版相同。
- **功能比 Python 版少**：没有看门狗 / 卡死自动重启，不会让位给 VBE 自己的成员列表，
  没有参数信息提示，也不收宿主枚举常量。
- 全局钩子只在 VBE 获得焦点时挂载：别的编辑器里没有补全，切回 VBE 有一小段延迟。
- 真机检查（`--carettest` / `--hktest`）需要打开带 VBA 的工程与代码窗，没有现场时只能跳过。
