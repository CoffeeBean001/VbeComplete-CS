# VbeComplete · C# 版

*[English](README.md) · 简体中文*

与 Python 版（同级目录 `..\VbeComplete-PY`）同一套 VBA 编辑器补全工具，用 C# 重写，独立仓库。
VBE 原生从不补全**你自己声明**的名字，本工具补的就是这一块。支持 **Office 全家桶**
（Excel / Word / PowerPoint / Access / Visio）与 **WPS 全家桶**，按前台窗口自动识别宿主。

C# 版存在的理由只有一个：**不在 VBE 代码窗里时，一个 COM 调用都不发**，空闲时消息循环不占 CPU。

## 功能

- **两个可编辑的词库**：`keywords-cs.db`（VBA 关键字 79 条）与 `functions-cs.db`
  （171 个函数 + 13 个类型）。标准 SQLite 文件，拿 DB Browser 当表格改，改完重启即生效；
  首次运行用内置种子自动建库。**枚举一律不收**（`vbRed` / `xlUp` 太多，弹出来只是干扰）。
- **实时候选**：标识符 / 声明 / 过程 / 模块 / 窗体 / 控件 / 词库里的关键字与函数。
- **模糊匹配**：整块连续 > 前缀 > 驼峰词首 > 分散，命中字符**逐个高亮** ——
  打 `ds` 命中 `dataSheet` 的 D 和 S（不是一整段），打 `ta` 命中 `dataArr` 的 `ta`。
- **中文名字照常提示**：`Sub 汇总()` / `Dim 学生 As String` 这类中文标识符能进候选池、
  能逐字符加粗标记、Tab 之后光标落位正确（真机已验证）。
- **排序照 IDEA 的口径**：命中质量 > 首个命中位置 > 命中跨度 > 作用域就近
  （本过程局部 > 本模块 > 别的模块 Public）> 最近使用 > 名字短的在前。
- **作用域过滤**：`Sub A` 里的 `Dim tmp` 不会跑进 `Sub B` 的候选里；别的模块
  `Private` 的东西也不会漏过来。反过来，别的模块 `Public` 的过程和变量**照常提示**。
- **尊重 `Option Explicit`**：模块写了强制声明，就没写 `Dim` 的名字**不进候选**
  （那在 VBE 里本来就编译不过）；没写 `Option Explicit` 时按"自动声明"处理，照常提示。
  窗体控件这类"本来就由宿主声明"的对象（出现过 `控件.成员` 或 `Set 控件 =`）不受影响。
- **不在该弹的地方弹**：`As` **或 `New`** 之后（只可能是类型名；`Set c = New |`、
  `For i As |`、过程参数里的 `As |` 都算，不只是 `Dim` 行）、`Dim` / `Public` / `Private` /
  `Global` 起名字的位置、正在打的这个词自己，一律不出候选。
- **类模块的成员不是裸名**：`cls1` 里的 `Public s1`，只能用 `c.s1` 访问、或在 `cls1`
  模块内部当裸名用；在别的模块里单独打 `s1` 是编译不过的，所以不进裸名池。
- **点号之后整个让给 VBE**：`student.` / `Range("A1").` / With 块里的 `.Size` 这些位置
  **一个候选都不出** —— VBE 自己的成员列表有真类型信息，比我们准。`Ctrl+Space` 是点名
  要列表，照弹；`MEMBER_POPUP=1` 恢复旧行为（代码里有 `Dim c As Cls1` /
  `Set c = New Cls1` 就按类型收窄，定不出类型则退回全工程候选）。
- **候选窗照 VBE 自带列表的样子做**（v139 起步，v140 改字体与选中色，v141 改字号）：白底、黑字、
  每行一个图标、1px 立体边框，宽度贴着最长候选收窄（上限 640px）、一屏最多 15 行，
  命中的字母只**加粗**、不涂色。字体**跟着 VBE 编辑器走**（读 `VBA\7.1 → 7.0 → 6.0`
  的 `FontFace` / `FontHeight`），并去掉 `Light` / `Thin` 这类字重后缀 —— 细体在小字号
  下就是"扁平"的来源；读不到或读到的是 `Courier New` 之类的出厂字体时，依次改用
  JetBrains Mono / Cascadia Mono / Consolas。字号默认比 VBE **小一号**（14pt 编辑器配 13pt），
  `POPUP_FONT_SIZE = 0` 仍是小一号、`-2` 小两号、正数直接指定。选中行是 VBE 那种
  **深蓝底白字**（`POPUP_SEL_BG` 可改），命中的字母在蓝底上改用亮黄。全自绘、**永不抢焦点**。
- **只有真的在打字才弹**：鼠标单击另一行上的变量名（或按方向键换行）只是移动光标，
  不再弹出候选窗 —— 判据是"当前行号变了就不是打字"，真打字时行号永远不变。
- **不跟 VBE 抢位置**：VBE 自己的成员列表一出现就让位 —— 哪怕我们的窗已经在屏幕上，
  也会在一个轮询周期内收起来；VBE 的参数信息窗
  （形参签名）画在光标下方时，候选窗整体下移，两个窗不互相遮挡。
- **只认 `Tab` 补全**：`Enter` 仍然是换行（误补全的代价太大）；`Sub` 补空格、
  `Function` 补 `()` 且光标在括号里；词库里的函数（`MsgBox` / `Split`…）一样补，
  行首直接写函数名也照样补；类型名（`String`）绝不补括号。注释 / 字符串里不打扰。
- **回车自动缩进 + 补结构收尾**：块结构开头（`If…Then` / `For` / `Do` / `While` / `With` /
  `Select Case` / `Sub` / `Function` / `Property` / `Type` / `Enum`）回车后新行深一级，并在下面
  补出 `End If` / `Next` / `Loop` / `Wend` / `End With` / `End Select` / `End Sub` …
  `Else` / `Case` 这类分支行先拉回层级。**判据按 Python 版 v80a 的完整口径**：下方压着
  同级的旧代码也照样补（先写了一个 `For`、再回到它上面补一个新的 `For` 是最常见的用法）；
  只有"下面已经挂着本块自己的收尾"或"那个更浅的收尾属于外层块"时才不补，绝不凭空多补一条。
  ★敲完最后一个字符**立刻**回车也不会漏：钩子那一侧只负责"先接管"，真正的判定在 UI 线程
  用真 COM 数据做（判不过就把回车原样还回去）；输入法正在组字时绝不接管（那是上屏键）。
- **`Shift+Enter`**：在当前行下方新起一行，不拆开本行。
- **退格两用**：删掉只有空白的整行；或把中间的空括号 / 空引号两端一起删掉。
- **自动配对** `(` `"`：中文标点档下补全角 `（）` / `“”`；右边已是收符号就跨过去；
  有选区时用符号包起来。
- **行操作快捷键**：`Ctrl+/` 注释切换（选中多行就逐行批量处理；小键盘的 `/`、`Ctrl+Shift+/` 也认） · `Ctrl+D` 复制行 · `Ctrl+K` 删行 ·
  `Ctrl+Shift+Enter` 上方插行 · `Ctrl+Shift+↑/↓` 跳到上一条声明 / 过程收尾行 ·
  `Ctrl+Shift+L` **一键重排缩进**（整模块；有跨行选区就只理选区。只改行首空白，
  行内字符一个都不动，所以最坏也只是"某行缩进不对"，按几下 `Ctrl+Z` 就回来）。
- **`Ctrl+Q` 代码片段库**：自己的 `snippets-cs.db`（SQLite，窗口标题上就写着这个文件名），
  项目里唯一的片段库文件。左侧两行式列表（标题 + 代码首行预览，搜索命中逐字符高亮），
  右侧编辑区，`Ctrl+N` 新建 / `Ctrl+S` 保存 / `Enter` 或 `Ctrl+Enter` 插入到光标处。
- **自适应轮询**：打字时 50ms、停手 150ms、不在 VBE 里 250ms；鼠标粘贴 / 别的程序改代码
  造成的文本变化只收起候选、不弹（`REQUIRE_KEY_TRIGGER`）。
- **托盘常驻 + 开机自启**：右下角常驻一枚深蓝 V 图标（`app.ico` 里放了
  16/20/24/32/40/48/64/128/256 九帧，16px 下也认得出）。右键菜单可以开关
  **「开机自动启动」**、打开日志、退出。开机自启写的是
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，**不需要管理员权限**；
  程序启动时会顺手把图标设成"始终显示"，免得被 Win11 折叠进 `^` 溢出区。

## 优点

- **不写 VBA 时几乎零开销**：约 0.13% 的一个核、私有内存 11.7MB —— 不在 VBE 代码窗里
  一个 COM 都不发（Python 版同场景约 2% / 29MB）。
- 启动快：单个约 350KB 的可执行文件（框架依赖），没有解释器预热。
- **词库和片段库都是标准 SQLite**，用任何数据库工具就能改；两个库与 Python 版完全独立，
  不共用任何文件。
- 所有快捷键遵守同一条铁律：**做不成就把原按键原样还回去**，不会静默吞键。
- **363** 条纯逻辑自检（模糊匹配 / 作用域 / `Option Explicit` / 中文标识符 / 成员补位 /
  候选窗切段 / 调用点判定 / `As`、`New` 抑制 / 逐行缩进格式化）+ 词库检查 +
  片段库检查 + 图标与自启检查 + 离屏渲染 + 七条真机探针（含 `Ctrl+Shift+L` 与走真钩子的回车补结构）。

## 缺点

- 需要 **.NET 10 桌面运行时**，且只支持 Windows。
- 必须勾选"信任对 VBA 工程对象模型的访问"（默认关闭），与 Python 版相同。
- **功能比 Python 版少**：没有看门狗 / 卡死自动重启，没有参数信息提示，
  不收宿主枚举常量；可选的 `MEMBER_POPUP=1` 成员列表只认 `Dim ... As` 与
  `Set ... = New`（不做返回值推断）。
- 词库只在启动时读一次，改完必须重启程序（刻意这样：把"文件被外部改动"挡在运行期之外）。
- 开机自启写的是当前用户注册表；个别安全软件会拦这一步（菜单里会提示"没设置成功"，
  日志里有原因）。图标想从 `^` 溢出区拖出来也可以手动拖。
- 全工程标识符每 2 秒重扫一次（`SCOPE_TTL`）；模块极多时第一次补全有几十毫秒延迟。
- 全局钩子只在 VBE 获得焦点时挂载：别的编辑器里没有补全，切回 VBE 有一小段延迟。
- 真机检查：`--enginetest` 跑的是**合成工程**（不需要宿主、不需要打开代码窗），任何机器上
  都会真跑；`--paretest` / `--carettest` / `--hktest` 需要打开带 VBA 的工程与代码窗，
  没有宿主时这三条会跳过。`--yieldprobe` 连采 5 次"VBE 自带列表此刻在屏幕上吗"——
  如果觉得让位不对，就在 VBE 列表弹着的当口跑它。
